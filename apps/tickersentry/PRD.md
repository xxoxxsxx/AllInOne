# TickerSentry（美股价哨）产品需求文档

- 版本：v0.3.1（Go 技术架构定稿，Twelve Data 时间字段修订，外部行情源待发布核验）
- 日期：2026-10-08
- 目标：在 NAS 上自托管，按多个指定时间或手动查询美股价格，并在达到多档买入、卖出目标价时通过 Bark 提醒。
- 状态：产品范围与首版技术架构已确定；常规时段为当前实现基线，免 Key 行情来源仍是发布阻断项。本文不是交易建议，也不执行交易。

## 1. 背景与目标

用户目前需要自行反复查看美股价格，容易错过预设的买卖价位。TickerSentry 提供一个单用户网页控制台：配置股票、各档目标价、查询时间、行情来源和 Bark；后台执行查询、判断和提醒；通过 GitHub 构建 Docker 镜像，部署到 NAS 并持久保存配置与触发记录。

**成功标准（首版）**：用户无需修改代码，即可在 NAS 上添加至少 10 只美股，每只设置多档买入/卖出价，设置一天内多个查询时间；能看见每次查询结果和失败原因；每次有效查询命中档位后收到 Bark 通知；容器重启后数据及配置仍在。

## 2. 已确认需求与首版假设

| 类型 | 内容 |
| --- | --- |
| 已确认 | 主要监控美股；每天可配置多个查询时间；每只股票可配置多个价格档位；可手动查询；使用 Bark 通知；预置行情 API 的 Key 可配置，未配置时查询公开接口；GitHub 打包 Docker 并部署 NAS。 |
| 首版假设 | 单用户自用；股票和美股 ETF，价格单位 USD；默认只按常规交易时段触发价格提醒；每次有效查询命中均尝试通知，受单股时段提醒上限约束。 |
| 首版假设 | 时间设置默认以 `Asia/Shanghai` 显示和输入，可改为 `America/New_York`；同一配置的所有时间点使用同一时区。 |
| 首版假设 | 手动查询返回所有股票的最新可用查询结果，同时执行与定时任务相同的触价规则；另有单独的“发送测试通知”，不依赖股价。 |

上述假设使第一版可落地，并不代表用户已确认；见第 10 节。

## 3. 范围与非目标

### 首版范围

1. 维护美股股票/ETF 监控列表：代码、可选备注、启用状态；代码统一转大写，允许常见美股代码中的点和连字符，重复代码不可添加。
2. 每只股票可新增、编辑、暂停和删除任意多个买入/卖出档位；每档包含方向、目标价（USD、正数）、可选备注和提醒状态。
3. 配置每天多个独立的 `HH:mm` 查询时间，可增删、启停；同一时间去重；显示时区与下次执行时间。未设置时间时仍可手动查询，且界面提示自动查询尚未启用。
4. 定时与手动查询展示每只股票的价格、行情时间、数据来源、查询时间及状态；支持查看最近的查询和通知记录。
5. 配置 Bark 服务地址和设备 Key；支持测试通知、通知发送结果与失败原因；通知按股票汇总本次触发的全部档位，避免一次发送大量消息。
6. 行情来源优先采用已配置的 API；未配置 API 时尝试无需用户密钥的公开来源。两种来源都必须向用户标明行情时间；延迟属性只有提供商明确给出或可验证时才标注具体时长，否则显示“延迟未知”，不承诺实时性。
7. 单实例 Docker 镜像、Docker Compose 示例、持久数据卷、健康检查、NAS 部署/备份说明；通过 GitHub Actions 构建并发布镜像到 GHCR（公开发布仓库/镜像前由用户决定）。

### 首版不做

自动下单、接入券商账户、持仓/收益计算、复杂图表、移动端原生应用、多用户/多设备通知、盘中连续流式监控、短信/邮件通知。盘前盘后提醒不在默认首版范围；如用户明确需要，应单独确认行情源权限和数据字段。

## 4. 核心用户流程

1. 首次启动：打开首页 → 配置 Bark 地址和设备 Key → 测试通知 → 可选配置行情 API 密钥 → 添加股票与目标价 → 添加多个查询时间。
2. 定时查询：到达某个配置时间 → 确认是否属于所选监控交易时段 → 获取每只股票的最新可用报价 → 校验行情时间与币种 → 保存结果 → 判断各档 → 经 Bark 推送命中档位 → 记录发送结果。
3. 手动查询：点击“立即查询” → 页面显示运行中与逐只结果 → 按同一规则判断命中档位；无需等待下一个定时点。
4. 每次有效查询都判断全部启用档位；相同档位持续命中也再次尝试推送。

## 5. 功能规则

### 5.1 时间与交易日

- 使用 IANA 时区处理夏令时；界面同时显示配置时区和下次执行的绝对时间。避免将美东时间写死为与北京时间固定时差。
- 默认仅常规交易时段判定自动提醒：美东时间 09:30–16:00，且以当年美股交易日、节假日及提前收市日历为准；假日、休市和非监控时段的定时任务记录“跳过”，不将旧收盘价当作当前触价。NYSE 公布常规时段和节假日信息：[交易时间与日历](https://www.nyse.com/trade/hours-calendars)。
- 手动查询允许在任何时候执行并展示最新可用报价，但必须标记“市场休市/历史最后报价”；仅当查询实际执行时仍处于常规交易时段，且报价满足同一有效性检查时才发送价格触发通知。NAS 离线期间错过的时间点不补跑，避免恢复时集中推送。
- 同一时间点若上一轮仍在执行，不并发启动下一轮；手动查询与定时任务共享同一执行锁。繁忙时手动请求返回“正在查询”和当前任务编号；定时任务记录“跳过（繁忙）”，不排队补跑。

### 5.2 行情与有效性

- 已配置行情 API 时，首版提供 **Twelve Data** 作为预置适配器：使用其 `/quote` 获取 `close`、`currency` 和可核验的更新时间。2026-10-08 实际 `demo` 响应只有 `last_quote_at`（Unix 秒）、没有 `last_update_at`；官方 `/quote` 文档将它描述为最近一分钟 K 线的时间，允许以此作为 `close` 的时间字段，并继续检查交易时段及新鲜度。Key 由用户自己提供，不得写入 Git 或镜像。官方文档：[Quote API](https://twelvedata.com/docs)。可扩展其他提供商，但首版不做通用任意 URL/JSON 解析器。
- Twelve Data 免费计划的额度和市场权限依其当时的订阅而定；设置页显示“启用股票数 × 每日查询次数”的基础日额度估算，并按每次查询的股票数提示每分钟额度风险；手动查询和失败重试额外消耗额度。批量接口依然按股票数计费，不能把当前免费额度或数据展示权限当作永久承诺。官方计划页：[Individual Pricing](https://twelvedata.com/pricing)。
- **未配置 API 的公开来源是必要功能，但来源尚未通过发布验收**：实施前必须选择允许此用途、无需用户 Key、返回 USD 价格和可核验行情时间的来源，在目标 NAS 网络上验证可用性及访问规则。公开网页内部接口不等于有服务承诺。当前验证中 Yahoo Chart 返回 HTTP 429；Nasdaq 网页接口虽可访问，但其网站条款限制自动采集，因此不能直接将两者写成可靠、合规的默认适配器。参考：[Nasdaq Legal](https://www.nasdaq.com/legal)。若找不到符合条件的来源，不能宣称“免 API 即可用”；发布前应与用户讨论调整此要求。
- API Key 已配置但请求失败时，不悄悄切换成另一个价格口径；明确报错并保留原数据来源。若行情源限流、无有效价格、无可靠行情时间、币种不符或行情过旧，仅展示错误/警告，不触发买卖提醒。`/quote.timestamp` 表示区间起点，不用它替代最近更新时刻；缺少已核验的价格对应时间时故障关闭触发规则；`last_quote_at` 可用于触价时间检查，正式账户仍需现场核对价格与时间的对应关系。
- 首版常规时段提醒要求**已核验的报价时间**属于当前交易日的常规时段，且相对取得报价时刻的年龄在 **-2–30 分钟** 内（负值仅用于容忍最多 2 分钟时钟偏差）；超过后可显示最后可用价格，但标记“过期”，不判断阈值。若官方返回语义与实测不一致，暂停该适配器提醒并重新核验。展示价格精度以来源为准，内部比较使用十进制数，避免浮点边界误差。
- 查询本质是离散快照：两个查询点之间曾触及又离开的价格可能完全捕捉不到；“触价”仅表示**某次有效查询价**满足档位，绝不表示持续盘中实时盯盘。

### 5.3 档位与通知

- 买入档：`有效查询价 <= 目标价`；卖出档：`有效查询价 >= 目标价`；等于目标价算命中。同一股票可同时命中多档，逐档记录触发状态，按股票汇总到一条 Bark 消息。
- 每次有效查询都判断全部已启用档位；持续命中同一档位也再次尝试通知。暂停或删除档位不推送；单股时段提醒上限仍生效。
- Bark 通知包含股票代码、方向与所有命中的目标价、实际查询价、行情时间、数据来源及“仅供提醒、非交易指令”说明。Bark 支持 JSON POST `/push`、`device_key`、`title`、`body`、`group` 等字段，见[官方教程](https://github.com/Finb/Bark/blob/master/docs/en-us/tutorial.md)。
- Bark HTTP 成功且响应体明确表示接受后才记录成功；请求失败在后续有效查询仍命中时再次尝试。超时导致结果不确定时可能重复通知，记录该情况，不承诺严格恰好一次送达。未配置 Bark 时页面仍显示命中但明确标识“未通知”。

### 5.4 页面与设置

- 首页：监控列表、最近价格/行情时间/来源、各档状态、下一次查询时间、手动查询按钮、上次成功/失败摘要。
- 股票详情：多个买入/卖出档位及备注，独立启停；显示最近查询和通知记录。
- 设置页：查询时间与时区、Twelve Data Key（可留空）、Bark 服务地址与设备 Key、发送测试通知；设置页直接显示已保存的密钥，支持查看、复制与修改；日志与导出不包含明文。
- 单人使用，无需登录或账号密码；打开首页即可操作，部署在可信局域网/VPN 中。

## 6. 数据与部署要求

- 数据对象及约束见第 6.3 节。股票、档位、时间表、设置、查询结果与通知尝试均持久化，密钥保存在服务端，设置页可查看。
- 使用单服务、单实例、SQLite 持久化；所有用户数据放在 Docker 挂载卷而非镜像层。升级和重启不得清除配置或已提醒状态；提供备份、恢复及回滚镜像步骤，回滚前备份数据卷。
- 以 Docker Compose 在 NAS 上运行；首次启动显示设置引导。镜像至少覆盖常见 NAS 的 `linux/amd64` 与 `linux/arm64`，最终以目标 NAS 的 CPU 架构为准。GitHub Actions 推送 GHCR 的方式参见[GitHub 官方指引](https://docs.github.com/en/actions/tutorials/publish-packages/publish-docker-images)。
- 外部连接仅面向选定行情服务与 Bark 服务；请求有超时、有限重试与限流，不在日志、镜像、仓库或通知正文中泄露 API Key、Bark Key 和管理员密码。包含健康检查及可读的失败日志。
- 不自动把 GitHub 仓库设为公开，也不自动创建公开 GHCR 包；发布可见性由用户决定。面向公网提供服务和第三方行情数据再分发不属于本首版目标。

### 6.1 技术选型与边界

**首版采用 Go 单进程、单容器、SQLite 本地数据库；不引入前后端分离、任务队列、Redis 或第二个服务。** 在单用户、约十余只股票、定时 HTTP 查询、长期运行于 NAS 的约束下，Go 的构建与部署方式更契合目标；不以性能作为选型理由。Python + FastAPI + `exchange_calendars` 的开发体验与交易日历成熟度更好，但首版没有数据分析任务，也不需要其数值计算生态。Go 的交易日历库已有可用实现，不能再以“必须自研交易日历”作为排除 Go 的理由。

| 部分 | 确定方案 | 原因 / 限制 |
| --- | --- | --- |
| Web | Go 标准库 `net/http`、`html/template`、`embed`，少量原生 JavaScript/CSS；同源页面和 JSON 接口 | 不使用 SPA、Node 构建链或外部 CDN；模板默认做 HTML 上下文转义。 |
| 后台 | 同一进程内一个定时循环；手动与定时查询共用一个 `runOnce` 和执行锁 | 不启动多副本；启动时校验数据卷写权限；停机时取消任务并关闭 HTTP 服务。 |
| 存储 | 标准库 `database/sql` + `modernc.org/sqlite`（无 cgo），显式 SQL/迁移（`PRAGMA user_version`）、本地持久卷 | 避免 NAS 跨架构 cgo 构建和独立数据库；启用 WAL、外键、busy timeout，限制连接池；不将 SQLite 放在 SMB/NFS 等共享文件系统。 |
| 时区/日历 | 标准库 `time` + `time/tzdata`，`go-marketcal` 的 NYSE 日历作为首选实现 | 取得当日实际开收市时间（含提前收市），并核对库的覆盖窗口；由于 Go 日历库相对年轻，依赖版本固定，发布前须逐年对照 NYSE 官方日历核验，超出已审查窗口时停止自动触价并提示更新；已公布但未收录的临时休市需管理员暂停提醒或升级日历库，不能声称程序会自动预知。 |
| 精确价格 | `shopspring/decimal` 从报价和目标价字符串解析、比较，SQLite 中保存规范十进制字符串 | 不经 `float64` 中转；限定输入长度与精度，拒绝非法数值。 |
| 外部 HTTP | 标准库 `net/http`；Twelve Data `/quote` 适配器；Bark `POST /push` | 客户端设置超时、不跟随重定向；报价标准化与触发判断分离。 |
| 请求保护 | 表单 CSRF token、来源检查 | 单人可信网络使用，无登录鉴权；变更接口保留 CSRF 和来源检查。 |
| 镜像 | 固定 Go/依赖版本的多阶段 Dockerfile，`CGO_ENABLED=0`，`linux/amd64` + `linux/arm64`；GitHub Actions + GHCR | 将模板、静态文件和时区数据嵌入程序；NAS 通过 Compose 使用固定版本标签而非 `latest`。 |

```text
浏览器 ──同源页面/JSON──> Go net/http ──显式 SQL──> SQLite（/data，本地卷）
                           │
定时循环 ──同一个 runOnce ──┤──> QuoteProvider ──> Twelve Data / 已验证公开源
手动查询 ──同一个 runOnce ──┘──> BarkClient ─────> Bark
```

仅运行一个应用实例；若未来需多副本，必须先拆分调度或加入数据库租约，**不能直接扩容容器**。`go-marketcal` 是首选候选而非对所有未来年份的正确性保证；当前实现只在已核验的 2026–2028 年日历窗口内触价，超出窗口即停止触价。首版不做“任意行情 API 可配置”：配置仅包括预置 Twelve Data 的 Key，以及通过发布验收后内置的免 Key 适配器。

### 6.2 应用接口与数据契约

- UI 路由：`/`、`/stocks/{id}`、`/settings`、`/runs/{id}`；同源 JSON API 以 `/api/` 为前缀，提供股票/档位/时间配置、`POST /api/runs`、`GET /api/runs/{id}` 和 `POST /api/bark/test`。表单或 JSON 写请求均需 CSRF token 和来源检查；`GET /healthz` 仅报告进程及数据库可读状态，不暴露配置。
- `POST /api/runs` 创建手动查询并返回任务 ID；浏览器轮询 `/api/runs/{id}` 查看逐只结果。若已有运行中的查询，返回现有任务 ID，不再创建第二轮；调用需通过 CSRF 和来源检查。
- `QuoteProvider.Fetch(ctx, symbol) (Quote, error)` 的标准字段：代码、USD 十进制价格、行情更新时刻（UTC）、数据来源、延迟标记（已知分钟数或“未知”）；提供商错误是显式状态，不伪造成 `Quote`。XNYS 作为首版统一的美股交易日历；不识别单个证券的临时停牌，因此必须同时验证行情更新时刻。只在服务端校验交易时段和行情新鲜度；前端仅显示结果。
- 所有内部时间用 UTC 存储，界面在配置时区显示；金额用规范十进制字符串存储并以十进制数精确比较，拒绝零值、负值、NaN/Infinity 和超出允许精度的输入。股票代码规范化后唯一；不通过代码格式推断其交易所或资产类型，行情元数据不符时不给提醒。

### 6.3 持久化模型（首版）

| 表 | 关键字段 / 约束 |
| --- | --- |
| `stocks` | `id`, `symbol UNIQUE`, `note`, `enabled`；删除前要求明确确认，关联档位级联删除，历史查询保留代码快照。 |
| `levels` | `id`, `stock_id`, `side` (`buy`/`sell`), `target` (十进制字符串), `note`, `enabled`；旧版提醒状态字段保留以兼容已有数据库和配置备份，但不再参与触价判断。 |
| `schedule_times` | `id`, `hhmm`, `enabled`, `UNIQUE(hhmm)`；`settings` 存统一 IANA 时区、Twelve Data Key、Bark URL/Key。 |
| `quote_runs` | `id`, `kind` (`scheduled`/`manual`), `slot_key`（定时任务以配置时区的本地日期 + `HH:mm` 标识，手动为空）、`slot_at`（实际匹配的 UTC 时刻，可空）, `started_at`, `finished_at`, `status`, `reason`；定时任务 `slot_key` 唯一，用于跨夏令时重复小时去重。 |
| `quote_results` | `run_id`, `symbol` 快照、报价十进制字符串、`quote_at`/`fetched_at` UTC、来源、延迟属性、有效性、错误码；不因同一股票后续删除而失去记录。 |
| `notifications` | 每只股票每次推送尝试一行，保存 `run_id`、代码、行情价与时间、档位 ID/代次/方向/目标价快照、状态（待发送/成功/失败/结果不确定）、时间、脱敏错误；不保存 Bark Key。 |

服务启动时生成随机 CSRF token，页面表单与查询请求携带该值；重启后刷新页面即可继续操作，无需 Cookie 或登录。旧数据库的管理员与会话表保留兼容，应用不再使用其鉴权。档位通知状态由 `generation == alerted_generation` 计算，不从某次 HTTP 发出与否推断。查询与通知记录默认保留 90 天、定期清理；活跃配置和已提醒代次不清理。数据库升级按版本顺序执行迁移，失败则停止启动并提示先恢复备份，不静默重建库。

### 6.4 调度、行情与通知的执行顺序

1. 调度循环每 15 秒计算当前配置时区的 `HH:mm`，只启动落在当前分钟且尚无相同 `slot_key` 记录的任务；**不会**补跑过去的分钟。夏令时缺失的本地分钟跳过，重复的分钟只执行一次；时区/时间修改立即作用于下一次调度，不追补历史。定时与手动共用进程内执行锁。
2. 创建运行记录，检查 XNYS 当日常规时段（采用 `[开市, 收市)`；提前收市使用日历收市时刻）；定时任务休市直接记“跳过”。手动任务仍查询并显示报价，休市时不推送。
3. 按股票逐只或小批取报价，遵守供应商每分钟额度；超额分批延后，不能在 UI 显示全部已完成。示例：10 只股票在 Twelve Data 页面目前标称的 Basic **8 API credits/分钟** 下至少分两批；批量 HTTP 请求**不**减少每只股票的计费。遇 429 按响应等待时间有限重试；额度不足时单只标记失败，其余继续。外部连接设超时，不在数据库事务内等待网络。
4. 标准化报价并逐只核对币种、资产与标识、更新时刻和当日时段；价格有效才从每个方向选一个最近命中的启用档位，并检查各档位当前时段额度。保存报价及通知尝试的档位快照，然后事务外对该股票发送**一条** Bark；确认结果后更新通知记录，发送中、成功及结果不确定占用对应档位额度。
5. Bark 失败/结果不确定时保留记录，下次**有效且仍命中**的查询重试。容器中断后把遗留“运行中/待发送”记录标为“中断/结果不确定”，不自动重播旧报价；下次新查询重新判定。发送成功但数据库提交前崩溃可能重复通知，承认“至少尝试一次、非恰好一次”边界。

### 6.5 安全、运维与交付顺序

- 按 2026-10-10 单人使用需求，打开首页即可操作，不再要求账号、密码或登录。任何能访问应用端口的人都可查看配置与操作，部署范围为可信网络。Compose 示例默认绑定 `127.0.0.1`。
- 设置中的外部 URL 只允许 `https://`（局域网自建 Bark 可显式启用 `http://`，界面警示）；不跟随重定向，阻止 loopback/内网目标的远程设置滥用并避免请求泄露 Key。自建 Bark 的内网目标由本机管理员明确允许，不默认开放任意内网探测。密钥仅在设置页明文回填；不记请求/响应正文或包含密钥的 URL；数据卷备份本身含密钥，需限制备份权限。
- Docker 容器使用非 root 用户、只读根文件系统（必要临时目录显式挂载）、一个本地 `/data` 卷；正常停机优雅停止调度和查询。备份运行中的 SQLite 用在线备份 API，不只复制 `.db` 主文件（WAL 可能另有未归档写入）；恢复前停止容器并保留原卷。镜像回滚如跨越不兼容迁移，必须连同升级前数据库备份一起恢复。
- 实施按可独立交付的两段：① Twelve Data Key + 完整股票/档位/日程/手动查询/Bark/持久化/镜像链路，标明“需自备 Key 的预览版”；② 免 Key 来源需先完成访问许可、时间戳语义、美元报价、目标 NAS 网络和限流实测，达标后才内置并宣布完整首版。不允许以来源失效后的网页抓取或旧价作为自动降级。交付前按第 7 节人工验收；不额外要求自动化测试。

## 7. 验收场景（人工验收，不要求新增自动化测试）

1. 在 NAS 添加 AAPL 与另一只美股；AAPL 设置两个买入档、两个卖出档；保存后刷新页面仍存在。
2. 配置每天至少三个不同时间点；显示的下次执行时间与所选时区一致，跨美东夏令时变更不漂移；重复时间不能保存两份。
3. 手动查询时，逐只展示价格、USD、行情时间、来源和明确的失败状态；无效代码和源限流不会显示为“成功”。
4. 用受控的有效报价验证 `<=`、`>=` 与等值边界；买入 200/180 时价格 190 只消耗 200 档，价格 180 或 160 只消耗 180 档，卖出反向选择。两方向同时命中只推送一条 Bark，分别消耗各自档位额度。
5. 同一档位连续两次有效查询命中时均尝试通知，容器重启后也适用；Bark 失败在下次命中时重新尝试。
6. 未配置行情 Key 时，公开来源在 NAS 实际网络与交易时段可查询并返回可核验时间；如做不到，第 10 节的发布阻断项必须先解决，不能将“取到页面或旧收盘价”算通过。
7. 周末、假日、提前收市之后及过期报价不触发价格通知；离线错过任务后恢复不集中补发。发布前将选用日历的 2026–2028 年交易日及提前收市与 NYSE 官方日历核对；日历超出已审查窗口时停止自动触价；如发现未收录的临时休市，管理员暂停自动提醒或更新版本，不能依赖库自动获知后续公告。
8. 从 GHCR 拉取并运行对应 NAS 架构镜像，使用 SQLite 在线备份并恢复后股票、时间、Bark 设置与提醒状态均完整；密钥备份受权限保护。
9. 10 只股票在 8 credits/分钟限额下分批执行，不发生静默限流或“部分失败却整轮成功”；进程中断后没有补推旧价，重新启用的档位可再次提醒。

## 12. 单人使用增强（2026-10-11）

### 12.1 提醒可用状态
- 首页显示触价通知规则、行情 Key、Bark 配置、已启用查询时间及当前交易时段。配置完成不等于真实设备送达。
- 每只股票展示最近报价是否具备触价条件及原因；按当前时间重新判断报价新鲜度、交易时段、时间字段和资产资格。无报价或查询失败应明确显示，不能将旧报价标为实时可用。
- 设置提醒价及查询时间后，自动查询与手动查询使用同一触价和 Bark 推送流程；保留交易日历、报价新鲜度、币种和资产校验。

### 12.2 目标价差距
- 首页和详情对每个档位显示距目标价的 USD 差额和涨跌百分比；以最近有效报价为分母，使用十进制计算。
- 买入目标低于现价显示“还需下跌”；卖出目标高于现价显示“还需上涨”。已经处于目标区间显示“报价已达目标（不代表已通知）”。无报价不计算。
- 保留行情时间，明确差距基于最近保存报价，暂停状态单独标示。

### 12.3 每次命中提醒
- 每次有效查询独立判断已启用档位；买入价低于或等于目标价、卖出价高于或等于目标价即命中。同一档位连续命中也尝试通知。
- 同一股票一次查询每个方向只选一个最近命中档位；买入选最低已命中目标价，卖出选最高已命中目标价，同价按创建先后选。两方向命中时合并一条通知，按档位分别计数。已选档位耗尽时不回退到其他已命中价位；所有启用档位都耗尽时停止该股时段自动查询。
- 历史配置的提醒模式、冷却时间及已提醒状态保留在备份中，但不影响后续命中判断。

### 12.4 页面配置备份与恢复
- 设置页下载带格式版本的 JSON 配置备份，包含股票、各档位及其提醒状态、查询时间、时区、行情 Key 和 Bark 配置。查询/通知历史仍由现有 SQLite 完整备份功能保存，页面清晰说明范围。
- 上传同格式备份后确认覆盖当前配置；校验文件大小（最多 2 MiB）、格式版本、价格、方向、股票唯一性、时间表和 Bark 地址。错误文件不得修改数据。
- 恢复以数据库事务原子替换配置，保留当前查询/通知历史；查询正在运行时拒绝恢复，避免配置与在途通知冲突。恢复不补跑任务、不自动推送。
- 备份含 Key，页面说明应妥善保存；不把配置传给外部服务。部署端口不纳入恢复。

验收：缺配置/休市/旧报价状态准确；涨跌差额与百分比正确；连续命中、失败重试和重启后的提醒符合规则；备份往返配置一致，非法文件及忙碌时恢复无副作用。


## 时间段查询与档位提醒上限（2026-10-15 更新）

- 自动查询页可添加、修改、暂停、恢复和删除每日查询时段，设置起止时间、查询间隔（分钟）及每个档位的默认上限；各档可在股票详情页单独覆盖，留空继承默认值。
- 每档默认上限初始为 3 次；自动查询页可统一调整所有时段的默认上限并作为新时段预填值，单独档位的覆盖值不变，已有次数不清零。
- 采用配置时区，支持跨午夜；起点执行，终点不执行，按起点对齐间隔。时段不可重叠，保留固定时间点，同一分钟合并执行。
- 每次有效报价买入选择已触及的最低目标价，卖出选择已触及的最高目标价，同价位只选创建最早的一档；已选档位额度耗尽也不转用其他档位。两方向同时命中合并一条通知，分别计数。Bark 成功、发送中和结果不确定占用次数，明确失败及未配置 Bark 不占用。
- 所有启用档位用尽后停止该股本时段自动查询，其他股票继续。下一时段恢复，跨午夜不重置，重启保留次数。手动查询可更新报价，受已选档位当前时段额度约束。
- 首页显示用尽档位数和停止状态，时段内直接在各目标价旁显示每档已提醒次数与上限；时段外展示自定义上限或继承提示。详情显示每档已用次数和上限。修改档位不清零，删除重建为新档位。
- 时段结束或暂停后，尚未发出的查询跳过；已发出的请求可返回报价，但不再触发该轮自动通知。离线任务不补跑。
- 正处于时段内时可调整间隔、提醒上限和暂停/恢复，次数不清零；结束后才能修改起止时间、删除或切换时区，避免改变当前计数归属。暂停仍保留上限。
- 继续遵守交易日历、有效报价要求和接口额度；设置页用量估算包含时间段查询，未扣除休市、重复时间点及提前停止，属于保守上界。
- SQLite 升级到版本 12，档位稳定标识避免配置恢复后旧通知占用新档位额度；完整数据库备份保留计数。JSON 配置备份为版本 4，兼容版本 1 至 3；配置备份不包含通知历史，新库恢复后次数从零开始。


## 2026-10-13 股票列表与收益预估

- 首页和股票详情提供醒目的添加按钮；弹窗支持“保存并继续添加”和“保存并设置提醒”，错误保留输入。
- 首页使用全宽横向列表，直接展示买入、卖出目标和每股预计收益；支持代码/备注搜索与监控状态筛选，手机端自动纵向排列。
- 每股预计收益 = 卖出目标 − 参考买入目标；收益率 = 差额 / 参考买入目标。多个买入目标默认选择最高价，可手动保存参考价，目标移除后回退到最高价。
- 预估不表示成交，不包含股数、手续费或税费。参考价保存在数据库及配置备份；旧配置缺省使用最高买入目标。

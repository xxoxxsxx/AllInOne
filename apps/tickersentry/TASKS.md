# TickerSentry 开发任务与阶段验收

依据 [PRD.md](PRD.md) v0.3.1，2026-10-08。本文是实施清单，不代表功能已实现。每一阶段结束都停下来做人工验收、记录问题，再进入下一阶段；不在此清单中预设自动化测试任务。

## 实施原则

- Go 单进程 + SQLite + 服务端模板；一份代码同时服务手动与定时查询。保留小型 `QuoteProvider` 边界，但不做通用 URL/JSON 配置平台。
- 每阶段产物可独立运行：阶段 1 可手动查价；阶段 2 可手动触价提醒；阶段 3 可自动执行；阶段 4 可在 NAS 部署带 Key 的预览版；阶段 5 才可能宣称满足免 Key 的完整需求。
- 所有阶段都执行 `go build ./...`（代码建立后）、启动应用并跑本阶段人工场景；未通过不进入下一阶段。用户未要求自动化测试，不新增测试文件。
- 第三方密钥只通过应用设置或部署环境提供；不进入 Git、镜像、示例配置和日志。外部服务失败必须显式展示，绝不以旧价或其他来源静默代替。

## 尽早核查的三个外部门槛（与阶段 1 并行）

- [ ] **Twelve Data 实际响应**：由用户自备免费 API Key，在常规交易时段实测 `/quote` 的 `close`、`currency`、`last_update_at` / `last_quote_at`、代码/资产信息、错误与 429 响应；核对时间字段语义和免费额度。未拿到 Key 时可先完成阶段 1 的本地功能，但不得声称真实行情链路验收通过或发提醒。
- [ ] **免 Key 来源资格**：核对来源条款是否允许 NAS 定时自动查询，是否无需用户 Key、返回 USD 与可信行情更新时间，是否能在目标 NAS 网络于常规时段稳定查询至少 10 只股票；记录采样时间、延迟、限流与失败行为。网页内部接口可访问不等于合格。若未找到来源，尽早向用户提出选择：保留“完整首版”发布阻断，或明确批准把需求改为“需配置免费 Key”；不得私自降级。
- [x] **交易日历证据**：锁定 `go-marketcal` 版本 `v0.0.0-20260802160815-d72677789409`，逐日列出 2026–2028 年节假日及提前收市，与 [NYSE 官方时间表](https://www.nyse.com/trade/hours-calendars) 核对，无不一致项。代码只允许该三年窗口触价和自动查询；未来官方修订或临时停市仍需人工处理。

## 阶段 1：手动查价的最小可用闭环

**交付物**：本地运行的受保护网页；配置 Twelve Data Key、股票并手动查询；结果和错误可持久查看。此阶段**不发送 Bark，也不自动查询**。

- [x] 建 Go 项目、启动入口、配置加载、模板/静态资源内嵌、`/healthz`，应用以单实例运行。
- [x] 建 SQLite 本地卷、版本化迁移、WAL/外键/busy timeout；持久化设置、股票、查询任务及逐股结果，设置页可查看已保存的密钥。
- [x] 按 2026-10-10 单人使用需求移除登录、退出和账号密码配置；保留 CSRF 和来源检查。
- [x] 实现股票添加/编辑/停用/删除与代码唯一性校验；实现设置页填写/更换 Twelve Data Key，回填已保存的 Key，支持查看与复制。
- [x] 实现 Twelve Data `/quote` 获取与 `QuoteProvider` 标准化：精确十进制价格、USD、更新时间 UTC、来源；超时、429、无效代码、缺字段逐股报错，不将 `/quote.timestamp` 当成更新时间。
- [x] `POST /api/runs` 创建手动查询任务，`GET /api/runs/{id}` 轮询逐股结果；同一时刻只运行一轮，忙时返回当前任务 ID；重启后遗留任务标记中断，不回放旧报价。
- [x] 首页、设置页、任务详情展示价格、报价时间、查询时间、来源、已知/未知延迟、失败原因；休市报价仅展示，不声称可触价。

**验收状态（2026-10-08）**：代码与本机人工烟测已完成；`demo` Key 仅能查 AAPL，实际返回 `last_quote_at`。正式 Key 的两股票、常规时段、429/缺字段场景尚未验收，不能将阶段 1 记为全部通过。

**验收 / 提前暴露的错误**：用真实 Key 在常规时段查 AAPL 和另一只股票；页面刷新和进程重启后查询记录仍在。用错误代码、失效 Key、限流及缺少可用时间字段的响应检查逐股失败；核验 `last_quote_at` / `last_update_at` 与 `close` 的实际对应关系；密钥仅在设置页显示，不出现在日志中。若真实数据字段/配额不符合预期，在此阶段调整适配器。

## 阶段 2：手动触价与 Bark 提醒

**交付物**：已有手动查价能力上，新增多档买卖阈值和可靠的 Bark 发送；无需等定时器即可实际使用。

- [ ] 增加档位 CRUD、启停、重新启用、`generation`/`alerted_generation`；精确十进制比较，买入 `<=`、卖出 `>=`，等于目标价算命中。
- [ ] 引入 NYSE 交易日历，按查询执行时刻判断常规时段、节假日和提前收市；校验报价属于当日常规时段、更新时间年龄为 -2～30 分钟、币种与标识匹配；过期、缺字段、休市均不触发。
- [ ] 配置 Bark 地址/设备 Key 与测试通知；使用 JSON `POST /push`，只有 HTTP 与响应体都确认接受才将对应档位代次标记为已提醒。
- [ ] 每只股票一次查询的全部新命中档位合并为一条推送；网络调用不持有数据库事务，保存通知尝试与结果，失败保留待提醒状态；超时结果不确定要可见，绝不承诺严格恰好一次。
- [ ] 股票详情展示多档状态、最近报价及通知记录；修改阈值会重置提醒时明确提示；未配置 Bark 时展示“命中但未通知”。

**验收 / 提前暴露的错误**：在开发环境用受控报价适配器人工演练等值边界、单股票多档、Bark 成功/失败、重复查询、重新启用和容器重启；周末、提前收市后、过期价、非 USD 不推送。线上实际推送另用有效 Key 与 Bark 设备确认；没有可验证的行情时间就停止触价。

**阶段 2 实施记录（2026-10-08）**：已实现档位、NYSE 常规时段/新鲜度校验、Bark 测试与逐股合并通知、失败/不确定记录及重启处理；`last_quote_at` 继续仅展示。`go build ./...`、`go vet ./...` 均通过；本地启动/初始化/登录、档位增改停启、Bark 配置脱敏与 v2→v3 数据保留烟测通过。受控适配器手动演练了等值、多档合并、失败后重试、重复查询、重新启用、休市/过期/未核验时间及未配置 Bark。2026-11-27 提前收市 13:00、2026-12-25 假日由日历返回预期结果。正式行情时间语义、NYSE 全年与异常休市日历、真实设备送达及完整手动查询到推送的端到端场景尚未人工验收，阶段 3 的进入条件仍未满足。

## 阶段 3：多时间点自动查询

**交付物**：在手动链路保持可用的前提下，新增每天多个时间点的自动查询与跳过记录。

- [ ] 增加查询时间 CRUD、去重、启停及配置时区（默认 `Asia/Shanghai`，可选 `America/New_York`）；持久化时间表并显示下次执行的绝对时间。
- [ ] 同进程定时循环复用阶段 1/2 的 `runOnce` 和执行锁；休市/超出审查窗口/上一轮繁忙时记录“跳过”，进程离线错过的时间点不补跑。
- [ ] 按供应商每分钟额度对 10 只股票分批；手动查询与有限重试也计入额度预算，429 只按服务端指示有限退避，失败逐股可见，不把部分完成标记为整轮成功。
- [ ] 页面展示下一次查询、当前进度和最近运行摘要；未配置时间时提示仅可手动查询。

**验收 / 提前暴露的错误**：配置三个不同时间点，检查美东夏令时切换前后、周末/假日/提前收市、重复时间、忙时手动与定时互斥；重启后不集中补跑。用 10 股检查免费额度分批和逐股错误，无静默限流。日历官方核验不通过时禁用自动触价。

**阶段 3 代码记录（2026-10-09）**：已实现时间表 CRUD、时区/DST、进程内调度及跳过记录；手动与定时共享执行锁和持久化的保守免费额度预算，逐股记录 429 与部分完成，首页展示下次执行、进度与摘要。自动通知默认禁用，仅在完成正式行情与日历核验后由部署者显式启用。`go build ./...` 与 `go vet ./...` 通过；本机初始化/登录/时间表页面及持久化、v3→v4 数据保留人工烟测通过；尚未完成 10 股真实行情、长期 DST/日历及自动通知端到端人工验收，阶段 3 **未正式验收**。

## 时间段查询与单股提醒上限（2026-10-12）

- 自动查询页可添加、修改、暂停、恢复和删除每日查询时段，设置起止时间、查询间隔（分钟）及每只股票的提醒上限。
- 采用配置时区，支持跨午夜；起点执行，终点不执行，按起点对齐间隔。时段不可重叠，保留固定时间点，同一分钟合并执行。
- 每只股票独立累计；同一通知合并多个命中价格只计一次。Bark 成功、发送中和结果不确定占用次数，明确失败及未配置 Bark 不占用。
- 达到上限的股票停止本时段后续自动查询；其他股票继续。下一次时段自动恢复，跨午夜不重置，重启保留次数。手动查询仍可更新报价，但不能突破当前时段上限。
- 每次有效查询命中均尝试提醒，仍遵守单股时段上限。首页显示每只股票本时段次数和停止状态。

**2026-10-15 调整**：每个方向一次查询只选最接近现价的已命中档位，按档位单独限制每时段提醒次数。旧版“仅一次”及冷却状态不参与判断。历史备份字段继续兼容；新配置备份保存档位上限。
- 时段结束或暂停后，尚未发出的查询跳过；已发出的请求可返回报价，但不再触发该轮自动通知。离线任务不补跑。
- 正处于时段内时可调整间隔、提醒上限和暂停/恢复，次数不清零；结束后才能修改起止时间、删除或切换时区，避免改变当前计数归属。暂停仍保留上限。
- 继续遵守交易日历、有效报价要求和接口额度；设置页用量估算包含时间段查询，未扣除休市、重复时间点及提前停止，属于保守上界。

- 首页和股票详情提供醒目的添加按钮；弹窗支持“保存并继续添加”和“保存并设置提醒”，错误保留输入。

- 预估不表示成交，不包含股数、手续费或税费。参考价保存在数据库及配置备份；旧配置缺省使用最高买入目标。

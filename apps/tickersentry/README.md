# TickerSentry（阶段 3/4 代码预览）

打开首页即可维护股票及多档买入/卖出目标价、手动查询 Twelve Data 行情，设置多时间点自动查询，并在有效命中时发送 Bark、飞书群机器人或 Telegram Bot 通知。**免 Key 来源尚未实现，NAS 实机部署尚未验收。**阶段计划见 [TASKS.md](TASKS.md)，规则见 [PRD.md](PRD.md)。

## 本地运行

需要 Go 1.25+。在项目目录执行：

```sh
go run . -data ./data -listen 127.0.0.1:8080
```

无需配置账号密码。浏览器打开 `http://127.0.0.1:8080/` 即可使用；在“设置”配置自己的 Twelve Data API Key 和至少一个通知渠道，发送对应测试通知，并在股票详情添加档位。飞书使用群自定义机器人的 Webhook，可选签名密钥；Telegram 使用 Bot Token 和数字 Chat ID，先在接收会话启动 Bot。旧 Compose 中的 `ADMIN_USERNAME` 和 `ADMIN_PASSWORD` 可以删除，保留也会被忽略。默认只监听本机。在「自动查询」页设置时间与时区；休市或任务繁忙会记录跳过，离线错过不补跑。手动及自动查询拿到有效报价并命中档位时，会向所有启用渠道发送。也可用 `DATA_DIR` 和 `LISTEN_ADDR` 环境变量设置路径和地址（命令行优先）。通过 HTTPS 反向代理访问时，设置 `PUBLIC_ORIGIN=https://你的域名`，以正确校验请求来源。

设置页可填写软路由 OpenClash 的 HTTP 或 SOCKS5 代理（例如 `192.168.5.1:7890`、`socks5://192.168.5.1:7891`）。保存前经代理访问 Telegram，页面显示该次 HTTPS 请求的响应耗时（ms）与测试时间，可重新测试或清除。耗时包含代理连接、网络和服务端响应，不等同于 ping，也不代表行情服务的延迟。容器内请使用软路由的局域网地址，确认已开启允许局域网连接。配置代理后 Twelve Data 行情查询使用代理，Bark、飞书及 Telegram 可各自选择代理或直连；测试通知沿用对应渠道的选择。旧配置升级时飞书和 Telegram 保持原有代理行为，Bark 保持直连。清除代理后所有渠道直连。配置备份包含代理地址与渠道选择；恢复带代理的备份也会先测试。

只在 NYSE 常规时段且已核验的 2026–2028 年日历范围内，使用匹配代码、USD、美股交易所及可识别的股票/ETF、`last_update_at` 或 `last_quote_at` 且年龄在 -2～30 分钟的报价触价。休市、提前收市后、缺少可用时间字段、过期行情都不推送。每次有效查询在买入和卖出方向各选一个最接近现价的已命中档位，按档位独立计数；一次命中每档只占一次额度。无启用渠道会记录“命中但未通知”，整轮显示部分完成。查询和通知历史按 UTC 日期保留至少 90 天，启动及每天清理；配置不清理。

NAS 上构建、安装与在线备份步骤见 [NAS.md](NAS.md)。`-backup <新文件>` 使用 SQLite 在线一致性快照，备份文件限本地用户访问。

仓库包含与 `cdk-ledger-app` 相同的 GitHub Actions → GHCR 流程：推送到 `main`、推送 `v*` 标签或手动触发时，自动构建 `linux/amd64` 与 `linux/arm64` 镜像并推送 GHCR。镜像带有分支、版本、短 SHA 标签；默认分支另有 `latest`。本地 `git commit` 不触发，需推送到 GitHub。NAS 可使用 [compose.ghcr.yaml](compose.ghcr.yaml) 拉取，具体步骤见 [NAS.md](NAS.md)。

数据目录包含行情与通知渠道密钥，不要放在共享网络文件系统；限制目录和备份权限。内网自建 Bark 的 HTTP/私网地址须显式允许；不要将服务直接开放公网。

**尚未验收**：需要用自己的正式 Twelve Data 账户在常规时段核验 `last_update_at` / `last_quote_at` 与 `close` 的实际对应关系、资产元数据、免费额度及 429 行为，并用有效 Bark 设备确认真实送达；确认前不要依赖自动交易决策。2026–2028 年的已公布 NYSE 假日及提前收市已与锁定版本日历逐项核对，但未来临时停市或日历更改仍需更新。没有真实 Key 或设备的本地构建/烟测不代表外部服务链路已通过。


## 时间段查询与档位提醒上限

- 自动查询页可添加、修改、暂停、恢复和删除每日查询时段，统一调整所有时段每档的默认提醒上限；新建时段预填该值，仍可单独修改时段默认值。股票详情页可单独设置某档上限；留空时继承时段默认值。首页在时段内展示每档已提醒次数与上限。
- 采用配置时区，支持跨午夜；起点执行，终点不执行，按起点对齐间隔。时段不可重叠，保留固定时间点，同一分钟合并执行。
- 买入选所有已触及目标中的最低价，卖出选已触及目标中的最高价；相同目标只选最早添加的档位。选中档位额度已用尽时不回退到较远档位。两方向同时命中各自计一次，向每个启用渠道发送同一条内容。任一渠道成功、发送中或结果不确定时占用一次额度；全部明确失败或未发送不占用。
- 一只股票所有启用档位的额度均耗尽后，停止本时段后续自动查询；其他股票继续。下一次时段自动恢复，跨午夜不重置，重启保留次数。手动查询仍可更新报价，但不能突破已选档位在当前时段的上限。
- 首页显示每只股票本时段用尽的档位数，详情页显示各档已用次数和上限。
- 时段结束或暂停后，尚未发出的查询跳过；已发出的请求可返回报价，但不再触发该轮自动通知。离线任务不补跑。
- 正处于时段内时可调整间隔、提醒上限和暂停/恢复，次数不清零；结束后才能修改起止时间、删除或切换时区，避免改变当前计数归属。暂停仍保留上限。
- 继续遵守交易日历、有效报价要求和接口额度；设置页用量估算包含时间段查询，未扣除休市、重复时间点及提前停止，属于保守上界。
- SQLite 升级到版本 13；完整数据库备份保留档位计数及逐渠道结果。JSON 配置备份升级到版本 5，兼容导入版本 1 至 4；配置备份不包含通知历史，恢复后新档位次数从零开始。


## 2026-10-13 股票列表与收益预估

- 首页和股票详情提供醒目的添加按钮；弹窗支持“保存并继续添加”和“保存并设置提醒”，错误保留输入。
- 首页使用全宽横向列表，直接展示买入、卖出目标和每股预计收益；支持代码/备注搜索与监控状态筛选，手机端自动纵向排列。
- 每股预计收益 = 卖出目标 − 参考买入目标；收益率 = 差额 / 参考买入目标。多个买入目标默认选择最高价，可手动保存参考价，目标移除后回退到最高价。
- 预估不表示成交，不包含股数、手续费或税费。参考价保存在数据库及配置备份；旧配置缺省使用最高买入目标。
